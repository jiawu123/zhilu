## 仓库基线与结构分析

开始视觉重构时的本地基线 commit 是 `804903d1ae4e10179f18fc66b6a6f5b11b9a3fdf`：

> fix: strengthen evidence planning and preview lifecycle

作者 JiayaoChen03，提交时间为北京时间 **2026-09-14 13:13:21**。该提交加强任务级证据校验和模型纠正边界，保留按周依赖窗口与无变化重排，恢复当前有效预览，并调整原文查看入口。远端检查受本机代理连接问题阻断，因此这里只确认本地 HEAD，不声称远端没有更新。

仓库的主要链路是：目标访谈 → 背景确认 → 研究准备 → 候选路线与对话调整 → 用户确认正式计划 → Roadmap → 事件与待确认差异 → 用户批准后创建计划版本。

| 层 | 职责与本轮判断 |
| --- | --- |
| `apps/web` | React 19 + Vite；Onboarding、ResearchStudio、Roadmap、抽屉和弹窗组成界面。全局 CSS 覆盖大部分表面，适合集中替换视觉体系。 |
| `apps/server` | 本地 API、访谈、研究编排、候选方案生命周期、重排与持久化组装；本轮未修改。 |
| `packages/contracts` | PlanNode、研究证据、事件和提案等共享契约；已有 `startDate` / `endDate`，因此无需增加截止日期字段。 |
| `packages/plan-engine` | 确定性校验、补丁应用、用户字段保护和计划版本；本轮未修改。 |
| `packages/agent-runtime` | Workflow 与 Roadmapper；本轮未修改。 |
| `packages/zhihu` | Python 检索与证据处理；本轮未修改。 |

需要保留的边界是：候选与正式计划分离、变更先预览后确认、用户手动字段受保护、证据不足明确展示。本次通过复用原组件和事件处理函数保留这些边界。视觉组件与业务编排仍集中在较大的 App 文件中，后续功能开发需要特别检查交互和持久化语义，不能仅以页面截图判断正确性。

## 已替换范围

- 目标输入、背景导入入口、多题型访谈、加载状态、背景摘要。
- 研究入口、候选路线比较、任务预览、对话区、证据展开、风险说明、确认区域。
- Roadmap 稀疏与密集画布、工具区、任务卡、状态、里程碑与目标。
- 项目抽屉、进度、本周焦点、历史与导出入口。
- 节点详情、编辑字段、任务依据、完成与归档操作区。
- 节点事件和时间约束事件弹窗、待确认差异、重排状态与错误反馈。
- 证据不足与工时超额等条件分支，以及窄屏布局、键盘焦点样式、减少动效偏好。

这表示现有页面和组件的视觉已替换，不表示所有业务路径已经通过真实服务端到端验收；实际走查覆盖和限制见 Dogfood 文档。

## 时间轴和截止日期

底部时间轴使用画布原有日期投影，同步横向拖动，并显示日期刻度与范围内的“今天”。任务卡、候选任务预览和侧栏任务展示现有 `endDate`，格式为“截止 YYYY/MM/DD”；详情中的原有日期编辑入口继续保留。

没有日期的数据显示“待安排”。本轮没有推算或写入新日期，也没有将截止日期改为必填，因为这会改变现有契约、校验或业务逻辑。若要求所有历史任务都必须有日期，需要在后续计划中处理缺失数据和必填规则。
