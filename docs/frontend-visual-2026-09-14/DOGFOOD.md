# Computer Use 走查记录与后续提升计划

日期：2026-09-14。对象：`codex/frontend-visual-copy` 上完成视觉替换后的前端。**本报告中的问题均未修复；走查后应用代码保持冻结。**

本次目标是记录实际可复现的技术问题和用户可能困惑的地方，并为下一轮工作提供可验收的计划。一次有限环境的走查无法证明不存在其他问题。

## 环境、数据与方法

- 使用 Codex 内置浏览器的 Computer Use，执行点击、输入、选择、拖拽、键盘操作、滚动、刷新、截图和只读 DOM / 控制台检查。
- 独立前端 `127.0.0.1:5178`、本地 API `127.0.0.1:8797`；数据位于 `/tmp/zhilu-visual-dogfood-data`，与原有开发服务和项目数据隔离。
- API 使用仓库原有 server 和 repository。为了离线覆盖访谈，临时测试入口通过现有注入接口提供固定的混合题型和摘要；此入口位于 `/tmp`，不属于应用修改。
- Live 研究和模型重排关闭，没有调用真实知乎或模型。503 在这里属于预期配置分支，不能当作生产服务故障。
- 通过界面创建 `project-e6cc7fcf`，目标为“在十二周内做出一个可以展示的小产品”，使用 Mock 的“先练基本功”路线。所有保存、确认和完成操作均发生在该临时项目。
- 另用 `dense-visual` 覆盖 16 个任务、多状态和缺失日期；用 `states-visual` 覆盖证据不足、工时超额和对话显示。它们是合成展示数据，不用于判断模型质量、证据准确性或契约通过率。
- 桌面主要为 1280×720 和 1440×900；窄屏为 390×844。内置浏览器随面板改变尺寸，部分截图尺寸不同，未将宿主缩放现象记录为产品缺陷。

## 已复现的技术问题

### DF-01 · P1 · 窄屏稀疏画布无法平移到路线末端

**复现：** 在 390×844 打开三个任务的 Roadmap，连续将画布向左拖动。

**实际：** `--pan-x` 停在 `-320px`，末段任务和目标仍在视口外，底部日期范围也不能完整到达。见 [截图 11](screenshots/11-mobile-pan-limit.png)。

**定位：** `App.tsx` 的 `moveCanvasPan` 在非密集模式使用固定 ±320px 边界；当前稀疏画布最小宽度为 1200px。这里是既有平移规则与当前布局的组合问题，不能仅用桌面截图验收。

**计划：** 下一轮按照实际画布、视口、顶部工具区和底部时间轴计算可视边界。验收 390 / 768 / 1280px 下所有任务和目标都可到达，回到全图有效，拖动不修改任务日期；时间轴持续与画布同步。

### DF-02 · P1 · 关闭的抽屉仍进入键盘焦点，弹层焦点管理不完整

**复现：** 关闭项目抽屉，从最后一个任务卡继续 Tab；打开任务详情或事件弹窗，再使用键盘导航 / Escape。

**实际：** 焦点落在 `.side-drawer[aria-hidden=true]` 内的“×”按钮；打开详情时焦点仍留在底层任务，事件弹窗按 Escape 未关闭。`aria-hidden` 与屏外变换不足以阻止焦点进入隐藏内容。

**计划：** 明确 drawer / dialog 的语义，为隐藏区域加入正确的不可交互处理，管理初始焦点、焦点循环和关闭后焦点归还。验收全程键盘可以完成查看、取消和确认；关闭区域不可聚焦；不改动保存或确认的业务回调。

### DF-03 · P1（内置浏览器）· “新路标”依赖不受支持的原生 prompt

**复现：** 在项目抽屉点击“＋ 新路标”，重复两次。

**实际：** 没有出现可用输入界面，控制台报 `Error: prompt() is not supported.`。见 [控制台记录](validation/console-errors.json)。`App.tsx` 的 `addTask` 直接调用 `window.prompt`。

**边界：** 只在本轮内置浏览器确认，未证明 Chrome / Safari 存在相同问题。

**计划：** 先跑浏览器矩阵，然后使用应用内可访问的输入对话框替代原生 prompt，复用原有命名校验与创建 API。验收取消不写入、空白不能提交、有效名称仅创建一次、异常可见且键盘可操作。

### DF-04 · P1 · 手动完成后记录节点变化被用户字段保护拦截

**复现：** 手动改名并完成首个任务，打开“这里有变化”，提交“走查样本：需要补充一次反馈记录。”。

**实际：** 页面显示 `Agent 不能覆盖用户字段：adjustmentReason`，无法继续。见 [截图 15](screenshots/15-node-event.png)、[截图 16](screenshots/16-manual-field-event-error.png)。

**判断：** 用户字段保护仍在生效；问题是节点事件与被保护字段之间缺乏兼容的处理路径，以及错误提示难以理解。不能通过放松保护或直接覆盖字段解决。

**计划：** 追踪事件转补丁的字段归属，明确用户操作与 Agent 提案如何保存变化原因。可能涉及 engine / server，属于后续功能范围。验收用户手动字段不被覆盖，节点事件能形成允许的预览或给出明确处理入口，确认前正式计划不变。

## 已观察到的体验疑点

### DF-05 · P2 · “接下来 7 天”可以显示数月后的任务

完成首个任务后，侧栏同一标题下展示 10 月和 11 月起始的任务。`roadmap-focus.ts` 在本周没有任务时会回退到未来任务，但界面标题固定。计划明确“本周”与“后续”的展示规则，再决定调整分组或文案；验收空周时用户不会把远期任务理解为本周到期。当前标题和筛选逻辑均保留。

### DF-06 · P2 · 同一编辑面板内的保存方式不一致

界面中状态选择与名称、日期、“保存修改”处于同一编辑区。代码确认状态的 `onChange` 立即调用保存，名称和日期依赖保存按钮。这是已确认的交互规则差异；本轮没有验证“未保存名称丢失”的完整路径，不能将其写成已复现数据丢失。计划先复现脏表单与状态切换，再确定统一提交或明确即时保存提示；验收保存时机可预测且无静默丢失。

### DF-07 · P2 · 长摘要和移动路线页的确认动作距离较远

摘要字段较多，路线页在窄屏依次堆叠候选、任务、对话和确认区域，用户需要较长滚动才能完成检查并确认。见 [摘要](screenshots/01-summary.png)、[窄屏路线页](screenshots/12-mobile-plan.png)。计划在保留必要告知的前提下，评估分段摘要和固定确认区；验收小屏能找到下一步，同时证据、风险与待确认状态不被隐藏。

### DF-08 · P2 · 图上位置与“截止日期”的时间语义需要说明

图中任务沿横轴使用原有 `startDate` 定位，卡片新增 `endDate` 截止标签。例如首项任务位于 09/14，但截止是 10/08。两者数据并不冲突，不过没有时长条或图例时，用户可能认为横坐标就是截止日期。见 [截图 05](screenshots/05-roadmap.png)。计划研究起止区间或轻量图例；验收用户可以区分开始、截止和预计投入工时，保持原排期值不变。

### DF-09 · P2 · 历史只显示最近五条，没有更早版本入口

临时项目达到 v6 后侧栏只显示 v6 至 v2，v1 不再显示；代码使用 `history.slice(0, 5)`。计划增加查看完整历史的可访问入口，复用现有历史数据；验收首次基线和后续变更都可追溯，无需修改已有记录。

### DF-10 · P2 · 技术术语与环境错误缺少面向使用者的解释

界面出现 Mock、unverified、PlanBundle，以及 DF-04 的 Agent 字段名。研究未配置场景是在研究步骤显示错误，用户不容易理解前置条件或后续路径。这里的访谈通过离线注入完成，因此不能据此断言真实未配置用户一定能先完成访谈。

计划在后续单独审阅文案和环境就绪提示，保留证据不足、未经验证和用户确认等必要信息，将字段名留在可展开的技术详情中。验收首次使用者能说明当前是演示还是真实研究、失败原因和可采取的下一步。本轮遵守文案冻结要求，没有改写这些文字。
