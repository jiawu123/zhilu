# 首次路线生成的引用与完整周覆盖纠正

日期：2026-09-13（本机时间；现场验证为 UTC 2026-09-14）。

## 现场问题与根因

用户在“我想成为小红书博主”完成访谈后，页面提示“路线依据必须用于具体任务，不能只作为装饰性引用”。项目 `project-901826b5` 的保存快照显示，两次研究已取得共 8 张证据，其中一项研究为 `partial`，整体进入证据不足的暂定模型规划。

错误来自 `compileRoadmapperBaseline`：路线总览的每一个 Evidence ID 必须至少出现在同路线的一项具体任务中。旧提示没有明确这项跨字段约束；模型输出被拒绝后，原 HTTP 流程直接返回错误，没有纠正机会。

原报错时的模型草稿未保存，不能逐项还原原始引用。用同样的跨字段不一致结构可以复现截图错误；另外复用本次实际研究快照，仅调用一次真实 M3，发现该次草稿没有引用错误，却遗漏最后的第 14 周，仍被完整周覆盖校验拒绝。最后一周只有一天，必须遵守其折算工时，不能直接省略。这进一步验证了对结构错误提供有限反馈纠正的必要性。

## 修改

- 生成提示明确路线引用与任务引用、推荐引用与推荐路线之间的关系；先判断依据如何影响任务，再汇总引用，禁止为过校验硬塞引用。证据不足时无实际用途的引用可以不列，并相应改写为待核实的 AI 判断。
- 明确 `weeks` 最后的不足七天的一周同样需要任务，使用其实际工时上限。
- 首次 live Baseline 在第一次模型草稿发生 `RoadmapperValidationError` 时，最多进行一次模型纠正。保留相同目标、确认条件、证据、周列表、工时策略和 Run ID，将旧草稿与具体错误作为不可信资料发送。
- 纠正后重新执行原 Roadmapper 校验与 Plan Engine 校验。未知来源、装饰性引用、超额工时、缺周、错误依赖、伪造批准字段仍被拒绝；程序不自动传播引用、删引用、改工时或制造来源。
- 网络/超时/协议错误不重试，第二次草稿不合格也不继续调用。Planner、知乎检索不重复。旧提案、正式计划和历史在新提案校验完成前保持不变，应用草稿仍需用户确认。
- 此自动纠正只接入首次 live Baseline；草稿对话修订及独立诊断回放仍为原来的一次模型调用。

## 后续核对：结构恢复不等于证据驱动

用户再次反馈步骤缺少知乎支持后，对上述恢复草稿逐项统计：**16 个任务中，引用知乎证据的任务为 0，引用用户事实 ID 的任务也为 0；路线引用列表为空**。研究快照实际有 8 张有效卡，包含账号定位和标题关键词等可供规划参考的内容。`insufficient` 允许引用数组为空，使这份纯 AI 推断草稿仍能通过结构校验。

因此，上述恢复只解决了结构错误和待确认草稿可读取的问题，**没有解决“知乎知识驱动任务”的产品要求**。不能将它作为证据采纳质量验收通过的记录；需要进一步区分证据整体覆盖不足与单条有效证据能否支持具体行动。

最新 `2026-09-14T03:52:22.174Z` 错误记录发生在 M2：首个研究请求返回 3 张卡，第二个请求以 `compilation_failed` 中断，第三个请求未执行。该次失败没有保存模型原始响应，现有错误映射也会把部分模型传输、JSON 和编译错误合并为同类，因此不能断言此次失败是语义筛选过严。已有合格卡与未知原因的编译失败应分别处理。
