# 等待反馈与直接确认

等待组件统一显示持续计时、小动画、当前动作和可展开的已执行步骤。访谈、知乎问题规划与逐问题研究、计划生成与调整、结构校验、一次纠错、事件重新排期均在实际执行边界上报；读取历史、保存回答和普通修改也显示等待状态。动画遵循减少动态效果设置。

每次请求使用独立 ID，进度按登录账号隔离，以只读接口轮询。轮询不重复提交原操作；原操作结束即清理。只返回服务端定义的动作说明，不传递模型隐含思考、私人输入或原始输出。知乎研究目前展示到逐问题检索与证据处理，未伪称已取得 Python 内部每个模型调用的流式状态。

调整区增加“直接确认当前计划”，沿用保存草稿接口，不再调用模型。调整期间禁用确认并解释原因，确认按钮不会因其他忙碌操作误显示“正在写入”。

## 耗时检查

调整仍要求模型完整输出路线 JSON，采用非流式响应；结构未通过时最多再纠错一次。这些工作均会延长等待，计时和阶段反馈本身不代表模型推理已提速。

用项目保存的研究快照和首次确认计划重建输入做只读估算：系统提示 3,235 字符，基本 context 7,292 字符，其中 8 张压缩证据 3,385 字符；当前草稿节点与依赖约 11,996 字符，合计约 22,523 字符，尚未计入完整调整对话。该数字不是原请求 token 实测值，不能单凭大小断定慢在上下文。

模型传输新增 `[model-timing]` 日志：输入字节数、响应头等待时间、总耗时、服务商返回的输入/输出 token 数及结果状态，不记录凭据或提示正文。非流式接口的响应头等待包含上游生成时间，不能将它单独解释成网络耗时。旧调用没有这些数据，无法补算本次原始请求的准确耗时分布。

## 验证

- HTTP 集成覆盖运行中的阶段读取、一次纠错、请求隔离、账号隔离、重复 ID 拒绝、直接确认不增加模型调用。
- 前端覆盖计时和阶段展示、轮询结束清理、网络失败不重试原操作；既有访谈与计划测试通过。
- Chrome 独立合成样例验证了真实服务端阶段切换、21 秒计时、纠错文案、完成后对话更新与直接确认进入路线图。样例模型使用延迟桩，无新增真实知乎检索或模型调用；未改写用户正式计划。
